# 项目进展

状态：实时链路可运行；核心状态识别在离线回放中验证，游戏内验证仍在进行。

## 已实现

| 模块 | 内容 |
|---|---|
| 抓帧 | Win32 `PrintWindow`（`PW_RENDERFULLCONTENT`，失败回退 0）+ GDI DIB，客户区裁剪，150% DPI 适配，黑帧检测 |
| 识别 | 纯 numpy/PIL，无 OpenCV；1920×1080 规范 ROI 自动缩放；二值掩码 NCC 模板 + 投影预筛 |
| OCR | PP-OCRv6 rec small ONNX（CPU），固定 ROI 只识别不检测；失败静默退回模板 |
| 状态机 | 4 fps 主循环，Bridge（帧→事件）+ Reactor（流程/战斗/商店），时间保持、去重、阈值 |
| 战斗 | 回合/倒计时/首领进度数字、四人血量、联防三点、扣血横幅、结算页颜色标记 |
| 商店 | 卡位占用、I–VI 徽章、道具图标、金币、购买/售出/升级/刷新/冻结/三连 |
| 语音 | winsound 异步播放；P0–P4 优先级 + TTL + 分类去重；变体随机；音量缓存 |
| 语音包 | `manifest.json` + wav 的 zip；路径穿越防护；解包缓存；热切换；打包工具 |
| GUI | 窗口选择、截图测试门禁、实时监控、调试面板、日志、参数与分类开关 |

## 已修复的关键问题

- 生命值 `14` 被读成 `4`：白字聚类间距固定 4 像素，缩放到 1600/2560 后「1」和「4」被切开；改为 `LIFE_CLUSTER_GAP=10`，薄「1」用 `LIFE_MIN_W=5`
- 生命值模板缺 `1`：模板候选集改为 life ∪ gold，并加截断护栏；0–9 字形已补齐
- Boss 击杀不播报：血条 ≤2.5%、低血后消失 0.5s、低血后红胶囊 3s 内消失、结算页兜底四条路径
- 扣血读数缺失时不再兜底成 `damage=1`，改为 `unknown` 并跳过伤势判断
- 冻结/解冻不响：READY 框与卡行重叠误清状态；新增浅蓝底双锚点、`unfreeze` 事件
- 休整误报：加入「休息一下」文字锚点 + HUD 三选一门禁，退出模式后的主页不再报休整
- 战斗结束/延误：`_final_last_t` 门禁避免死亡过场误报进入战斗

## 已知问题与限制

1. 游戏窗口判定使用标题/进程名子串匹配，窗口标题含 `arknights` 的非游戏窗口（如资源管理器）会被标成游戏
2. OCR 加载异常被静默吞掉，没有 `last_error` 落盘；出问题时只能看到文字锚点全部读空
3. `_life_pre` 不在 `_reset_run_flags` 中清空，跨局/中途进入时战前快照可能来自上一局
4. 扣血红字 `read_damage` 仍使用 `min_w=8`；720p 下红字「1」正好 8px，缩放偏差会切不出
5. `known_keys()` 仍包含无语音文件的 `level_read_1..10`；打包工具会提示这些 key
6. 语音包解包时文件名按纯文件名归组，zip 内带子目录的包在解包阶段可能对不上；已存在的非空截断文件会被复用；解压没有体积上限
7. 截图测试失败时只清空抓帧读数，其他调试读数保留上一帧的值
8. 日志文件打不开时没有兜底路径，后续日志只在内存里
9. 空格键只在文本框中排除，在 Spinbox/Combobox 中会触发暂停
10. 仅对 16:9 做了系统化验证；其他比例的 ROI 独立缩放，未实测
11. 商店徽章 III/IV、等级数字 III/IV 目前由规则推断，缺少实拍样本
12. 售卖按钮模板缺失时 `_sell_button` 会 fail-open（按「不可售」处理）
13. 游戏内验证不完整：雪地/等级/Boss 已通过；生命值修复后的版本尚未在游戏内复测
